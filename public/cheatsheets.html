AI Agents01 / 05
Los 12 fundamentales
  • LLM — predicción de tokens, stateless.
  • Prompting — system = config, user = request.
  • Structured Outputs — output validable por schema.
  • Function Calling — LLM propone, backend ejecuta.
  • Agent — loop pensar→actuar→observar.
  • Orchestration — coordina tools/pasos/agentes.
  • RAG — consulta en runtime, no fine-tuning.
  • Embeddings — similitud semántica vectorial.
  • Context Window — presupuesto de tokens.
  • Memory — short (sesión) / long (store externo).
  • Hallucination — falla con confianza, sin error.
  • Guardrails — middleware de validación.

Security03 / 05
"Un agente enterprise no debe tener autonomía ilimitada."
Identity & Data
  • OAuth2/OIDC/JWT — scope = exactamente el permiso del usuario.
  • Nunca secrets crudos en el contexto del LLM.
  • PII: minimizar lo que entra al contexto, no solo lo que se persiste.
Governance
  • RBAC por tool, según rol del usuario.
  • Audit log: quién, qué tool, con qué args, resultado.
  • Human-in-the-loop para acciones irreversibles.
AI Security (OWASP-style)
  • Prompt injection — tratar contenido externo como dato, nunca instrucción.
  • Excessive agency — se arregla con arquitectura (scope mínimo), no con el prompt.
  • Data exfiltration — allowlist de destinos, no fetch arbitrario.
  • Insecure output handling — output del LLM = input no confiable.
Distributed Systems & Cloud04 / 05
Conceptos clave
  • CAP — durante partición: consistencia o disponibilidad.
  • Saga — pasos con compensating actions, no ACID distribuido.
  • Outbox — evento + cambio de estado en la misma tx local.
  • Idempotency — key generada al iniciar, no en cada retry.
  • Exactly-once — no existe; se simula con at-least-once + idempotency.

Framework CDRT-R

Context → Decision → Reason → Trade-off → Result. 60-90s por decisión técnica.

STAR + Architecture Context

Situation, Task, Action, Result + el detalle técnico específico de la decisión.

Presentación ejecutiva

Conclusión primero, detalle técnico si preguntan.

Technical English
  • "Let me clarify the requirements first."
  • "There are two main trade-offs here."
  • "The bottleneck is likely to be..."
  • "I'd introduce async processing if volume grows beyond..."
  • "The main risk with this approach is..."
  • "Let's walk through the failure path."
  • "I'll assume X — correct me if that's wrong."
